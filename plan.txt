8. RULE-BASED CV MATCHING ARCHITECTURE AND SCORING FORMULA
--------------------------------------------------------------------------------
8.1 Elimination of External AI APIs:
    - Fully replace Services/AIMatchingService.cs runtime calls to Google Gemini with a deterministic, local, rule-based screening engine: RuleBasedMatchingEngine (or refactored AIMatchingService).
    - Preserves exact database models: AIMatchingResult (MatchingScore, Decision, MatchedSkills, MatchingDetails, EvaluatedAt) and JobApplication.Status remain unchanged.
    - Zero external network requests, zero API key configuration needed, 100% reproducible results, zero ongoing cloud inference cost.

8.2 Normalized 100-Point Scoring Breakdown:
    The final score is composed of 4 transparent, auditable weighted categories:

    CATEGORY 1: REQUIRED TECHNICAL SKILLS (Weight: 45 Points)
    ----------------------------------------------------------
    - Input: JobRequirement.RequiredSkills (comma, semicolon, or newline separated keywords).
    - Processing:
        * Parse job required skills into a list of normalized skill tokens.
        * Normalize aliases (e.g. "C#", "csharp", "c sharp"; "ASP.NET", "aspnet", "asp.net core"; "JS", "JavaScript", "ECMAScript"; "Postgres", "PostgreSQL").
        * Perform word-boundary regular expression matching against extracted CV text:
          \b(?:c#|csharp)\b (case-insensitive).
    - Formula:
        SkillMatchRatio = MatchedRequiredSkills.Count / TotalRequiredSkills.Count
        Score_Skills = Math.Round(SkillMatchRatio * 45, 2)
    - Edge Case: If no required skills specified in job circular, award full 45 points.

    CATEGORY 2: REQUIRED QUALIFICATIONS & ACADEMIC LEVEL (Weight: 25 Points)
    ------------------------------------------------------------------------
    - Input: JobRequirement.RequiredQualifications.
    - Hierarchy of Academic Credentials:
        * Level 5: Doctorate / PhD
        * Level 4: Master's Degree (MSc, MBA, MS, M.Tech, M.A.)
        * Level 3: Bachelor's Degree (BSc, B.Tech, BBA, B.E., B.A., Undergraduate)
        * Level 2: Diploma / Associate Degree
        * Level 1: Higher Secondary / High School
    - Processing:
        * Identify the minimum required level from JobRequirement.RequiredQualifications.
        * Scan CV text for highest degree mentions and field of study keywords (e.g. "Computer Science", "Engineering", "Business").
    - Formula:
        * If CV degree level >= Job required level: Award 20 points (Base Degree Met).
        * If relevant field of study keyword also matches: Award additional 5 points (Total 25 points).
        * If degree level is 1 tier below required: Award 10 points.
        * If degree level is 2+ tiers below: Award 0 points.
    - Edge Case: If no specific qualification required, award full 25 points.

    CATEGORY 3: EXPERIENCE DURATION & SENIORITY (Weight: 20 Points)
    ---------------------------------------------------------------
    - Input: JobRequirement.RequiredExperience (e.g. "3 years", "5+ years", "Senior").
    - Processing:
        * Extract target required years using regex: (\d+)\+?\s*(?:year|yr)s?.
        * Scan CV text for employment durations:
          a) Explicit duration phrases (e.g. "4 years of experience", "5 yrs experience").
          b) Work history date ranges (e.g. "2021 - 2025" -> 4 years, "2019 to Present" -> calculated years).
          c) Sum total verified experience across identified roles.
    - Formula:
        * If DetectedYears >= RequiredYears: Award full 20 points.
        * If DetectedYears < RequiredYears and RequiredYears > 0:
          Score_Experience = Math.Round((DetectedYears / RequiredYears) * 20, 2).
    - Edge Case: If no experience required (Entry Level / Fresh Graduate), award full 20 points.

    CATEGORY 4: PREFERRED SKILLS & ADDITIONAL CRITERIA (Weight: 10 Points)
    ----------------------------------------------------------------------
    - Input: JobRequirement.AdditionalRequirements.
    - Processing:
        * Extract non-mandatory skill keywords and bonus certifications (e.g. "AWS certified", "Docker", "Agile", "Scrum", "Git").
        * Match against CV text.
    - Formula:
        * Proportional match of preferred criteria:
          Score_Preferred = Math.Round((MatchedPreferred.Count / TotalPreferred.Count) * 10, 2).
    - Edge Case: If no additional requirements specified, award 10 points.

8.3 Final Composite Score & Decision Formula:
    TotalScore = Math.Clamp(Score_Skills + Score_Qualifications + Score_Experience + Score_Preferred, 0, 100)

    Decision Rules (matching existing recruitment workflow):
    - TotalScore >= 80.00% -> Decision: "SHORTLISTED"
      * Application Status updated to: JobApplicationStatus.Shortlisted
      * Eligible for formal Offer generation in OffersController.
    - 60.00% <= TotalScore < 80.00% -> Decision: "MANUAL REVIEW"
      * Application Status updated to: JobApplicationStatus.ManualReview
      * Candidate flagged for human HR screening; can be manually upgraded to Offer.
    - TotalScore < 60.00% -> Decision: "REJECTED"
      * Application Status updated to: JobApplicationStatus.Rejected

8.4 Explainable Audit Details Structure:
    The AIMatchingResult.MatchingDetails text column will store structured, transparent explanations formatted as:
    -----------------------------------------------------------------------------
    MATCHING BREAKDOWN (Score: {TotalScore}% — {Decision})
    • Technical Skills ({Score_Skills}/45 pts):
      - Matched ({MatchedSkillsList}): {List}
      - Missing Required Skills: {MissingList}
    • Qualifications & Education ({Score_Qualifications}/25 pts):
      - Target Level: {RequiredLevel} | Detected CV Level: {DetectedLevel}
      - Discipline Match: {DisciplineDetails}
    • Professional Experience ({Score_Experience}/20 pts):
      - Required: {RequiredYears} yrs | Detected: {DetectedYears} yrs
    • Preferred Criteria ({Score_Preferred}/10 pts):
      - Matched: {MatchedPreferredList}
    -----------------------------------------------------------------------------
    Recruiter Guidance: Score represents deterministic rule compliance based on extracted document text. Final hiring authority resides with the recruitment panel.

9. CV PARSING AND ERROR HANDLING
--------------------------------------------------------------------------------
9.1 Supported CV File Types:
    - PDF (.pdf) via UglyToad.PdfPig library (already installed, version 0.1.16).
    - Microsoft Word OpenXML (.docx) via DocumentFormat.OpenXml (already installed, version 3.5.1).
    - Rejection of legacy binary Word formats (.doc) with user-friendly guidance to save as .docx or .pdf.

9.2 Fix for Existing Code Defect:
    - File: Services/CVTextExtractionService.cs line 118-120:
      CURRENT CODE (Causes warning and potential NullReferenceException):
          var body = document.MainDocumentPart?.Document.Body;
      CORRECTED CODE:
          var body = document.MainDocumentPart?.Document?.Body;

9.3 Parsing Failure Modes & Defensive Strategies:
    - Failure Mode 1: Scanned image PDF without selectable text (OCR-less PDF).
      * Handling: Check if extracted text length < 50 characters.
      * Action: Throw descriptive UserFriendlyExtractionException("The uploaded PDF appears to be a scanned image or empty. Please upload a PDF containing selectable text or a Word document (.docx).").
      * UI Impact: Catches exception in HRApplicationsController.AIMatch, displays informative TempData["Error"] banner without crashing.
    - Failure Mode 2: Password-protected or encrypted document.
      * Handling: Catch PdfDocumentException / OpenXmlPackageException.
      * Action: Log warning and inform HR that document is encrypted.
    - Failure Mode 3: Malformed or corrupted file header.
      * Handling: Catch IOException / InvalidDataException gracefully.
    - Failure Mode 4: Path traversal attempt.
      * Handling: Preserve existing check:
        if (!fullPath.StartsWith(secureRoot + Path.DirectorySeparatorChar, StringComparison.OrdinalIgnoreCase))
            throw new UnauthorizedAccessException("Access denied.");

        * National ID numbers and Residential Addresses.
    - Scoring is strictly bounded to qualifications, technical skill keywords, and verified duration of experience.

11.3 Antiforgery & State Integrity:
    - All HTTP POST actions enforce [ValidateAntiForgeryToken].
    - Offer creation prevents duplicate offers via database queries.
    - Expired deadlines automatically block offer acceptance.
